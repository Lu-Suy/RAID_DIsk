# ZFS, RAID-Z et stockage avancé

## 1. ZFS — le cadre

**ZFS** n’est pas juste un système de fichiers.
C’est un **système de stockage complet** qui gère :
- le volume
- le système de fichiers
- l’intégrité des données
- les snapshots
- la redondance

Contrairement à un RAID classique + un filesystem séparé, ZFS gère beaucoup de choses **en une seule couche**.

### Ce qui le rend fort
- **checksums** sur les données
- détection de corruption silencieuse
- snapshots très pratiques
- scrub (vérification d’intégrité)
- gestion flexible des disques

En résumé :
ZFS est conçu pour la **fiabilité des données**, pas seulement la disponibilité des disques.

---

## 2. RAID-Z / Z2 / Z3

Dans ZFS, on ne parle pas exactement de RAID 5 / 6 classiques, mais de **RAID-Z**.

### RAID-Z1
- équivalent conceptuel du RAID 5
- **1** parité
- tolère **1** disque en panne

### RAID-Z2
- équivalent conceptuel du RAID 6
- **2** parités
- tolère **2** disques en panne

### RAID-Z3
- **3** parités
- tolère **3** disques en panne
- utilisé sur de très gros pools où le risque de multi-pannes est pris au sérieux

### Différence importante avec le RAID classique
ZFS est plus “intelligent” sur l’intégrité :
il ne se contente pas de reconstruire un disque,
il vérifie aussi que les données restent cohérentes.

## 3. RAID logiciel vs RAID matériel

### RAID matériel
Géré par un **contrôleur RAID** dédié (Dell PERC, HPE Smart Array, etc.).

**Avantages**
- transparent pour l’OS
- souvent très bon en production serveur
- pilotable via iDRAC / iLO
- hot-swap bien intégré

**Inconvénients**
- dépend du contrôleur
- moins flexible
- parfois plus fermé

### RAID logiciel
Géré par l’OS :
- mdadm (Linux)
- Storage Spaces
- ZFS
- etc.

**Avantages**
- flexible
- indépendant d’une carte propriétaire
- très puissant avec ZFS

**Inconvénients**
- dépend plus de la machine / OS
- un peu moins “plug and play” selon les cas
- la perf dépend de l’implémentation

### En datacenter
Les deux existent.
- Serveurs classiques constructeur → souvent **RAID hardware**
- Infrastructures modernes / homelab / cloud privé → souvent **RAID logiciel / ZFS / Ceph**

---

## 4. Et Ceph ?

**Ceph** va encore plus loin.

Ce n’est plus du RAID local sur un serveur.
C’est du **stockage distribué** sur plusieurs machines.

Idée :
- les données sont réparties sur un cluster
- redondance entre nœuds
- scalable horizontalement

Donc :
- RAID = protection au niveau d’un serveur / d’une baie locale
- Ceph = protection et distribution au niveau d’un cluster

Très utilisé dans les grosses infrastructures cloud / software-defined storage.

## 5. Comment situer tout ça

| Technologie | Niveau | Idée principale |
|------------|--------|------------------|
| RAID 0/1/5/6/10 | Local | Perf / redondance disque |
| RAID hardware | Local | Contrôleur dédié |
| RAID logiciel | Local | Géré par l’OS |
| ZFS / RAID-Z | Local avancé | Intégrité + snapshots + redondance |
| Ceph | Distribué | Stockage cluster multi-serveurs |

---

## 6. Ce qu’il faut retenir 

Pour un poste **Data Center Technician**, priorité :
1. RAID 0 / 1 / 5 / 6 / 10
2. RAID hardware + iDRAC/iLO
3. savoir qu’il existe du RAID logiciel
4. savoir que ZFS / Ceph existent dans les environnements plus avancés



---

## Phrases simples

- **RAID classique** = disques assemblés pour perf et/ou redondance
- **ZFS** = stockage intelligent avec intégrité des données
- **RAID-Z2/Z3** = versions ZFS avec 2 ou 3 parités
- **Ceph** = stockage distribué sur plusieurs serveurs
