# RAID 5 — En profondeur

## 1. Le cadre

Le **RAID 5** est un mode de type **striping avec parité**.

L’idée :
- on découpe les données sur plusieurs disques (comme le RAID 0)
- **et** on ajoute une information de parité
- cette parité est répartie sur l’ensemble des disques

Grâce à cette parité, si **un disque** tombe, on peut reconstruire les données manquantes.

C’est historiquement l’un des RAID les plus populaires, parce qu’il offre un bon compromis entre :
- performance
- capacité utile
- sécurité

---

## 2. Comment ça fonctionne concrètement

Minimum : **3 disques**

Exemple avec 3 disques :

Pour un ensemble de blocs de données :
- disque 1 → bloc de données A
- disque 2 → bloc de données B
- disque 3 → parité de A et B

Au bloc suivant :
- la parité change de disque
- elle “tourne” sur le groupe

C’est ça, la parité **distribuée**.

### À quoi sert la parité ?
La parité est une information calculée qui permet de retrouver une donnée manquante.

Si un disque disparaît :
- le système utilise les données restantes + la parité
- pour reconstruire ce qui manque

---

## 3. Ce que le RAID 5 apporte vraiment

### Sécurité
- tolère la perte de **1 disque**
- le volume peut continuer à fonctionner en mode dégradé

### Capacité
Meilleure que le RAID 1.

Formule simplifiée :
> capacité utile ≈ (n - 1) × taille du plus petit disque

Exemple :
- 4 disques de 1 To en RAID 5
- capacité utile ≈ **3 To**

Tu “perds” l’équivalent d’un disque pour la parité.

### Performance
- **Lecture** : bonne (souvent très correcte)
- **Écriture** : moins bonne que RAID 0 ou RAID 10

Pourquoi l’écriture est plus lourde ?
Parce qu’à chaque écriture, le système doit aussi recalculer et écrire la parité.

C’est le point faible du RAID 5.

---

## 4. Que se passe-t-il quand un disque tombe ?

1. Un disque tombe
2. Le volume passe en **degraded**
3. Le service peut continuer
4. On remplace le disque
5. Le système lance un **rebuild**
6. Pendant le rebuild, il recalcule les données manquantes grâce à la parité
7. Une fois terminé, retour à l’état optimal

### Point critique
Pendant le rebuild :
- le système est plus sollicité
- les disques restants travaillent fort
- si un **second** disque tombe pendant cette phase → **perte possible de tout le volume**

Sur de gros disques modernes, un rebuild peut être long.
C’est l’un des vrais risques du RAID 5 aujourd’hui.

---

## 5. Dans quels cas on l’utilise

### Cas où le RAID 5 reste pertinent
- serveurs de fichiers
- volumes de données généraux
- environnements où l’on veut un bon ratio capacité / sécurité
- infrastructures pas trop extrêmes en écriture

### Cas où il est moins idéal
- bases de données très intensives en écriture
- environnements ultra-critiques
- très gros disques avec rebuild très long
- besoins de forte résilience

Dans beaucoup d’environnements modernes, on lui préfère souvent le **RAID 10** quand le budget le permet.

---

## 6. RAID 5 en datacenter / serveur pro

En pratique, un technicien voit le RAID 5 via :
- iDRAC / iLO
- le contrôleur RAID
- les logs disque / virtual disk

États fréquents :
- Optimal
- Degraded
- Rebuilding
- Failed

Quand un disque est en prédiction de panne ou failed :
1. identification du slot
2. vérification de l’état du virtual disk
3. remplacement du disque
4. suivi du rebuild
5. validation du retour à Optimal

Le RAID 5 est très présent dans les serveurs “classiques”.

---

## 7. RAID 5 vs sauvegarde

Comme toujours :
**RAID 5 ≠ sauvegarde**

Il protège contre la panne d’un disque.
Il ne protège pas contre :
- suppression
- corruption logique
- ransomware
- erreur d’administration

Il faut toujours une stratégie de backup à côté.

---

## 8. Ce qu’il faut retenir sur le RAID 5

| Critère | RAID 5 |
|--------|--------|
| Performance lecture | Bonne |
| Performance écriture | Moyenne |
| Sécurité | Tolère 1 disque |
| Capacité utile | (n - 1) |
| Complexité | Moyenne |
| Usage principal | Compromis capacité / sécurité |

---

## 9. Phrase simple à retenir

**RAID 5 = données réparties + parité. Un disque peut mourir, le volume peut survivre. Mais pendant le rebuild, il faut faire attention.**
